# MUSABLAB architecture v0.1

MUSABLAB separates the **control plane** from the **test plane**.

- Control plane: GitHub HTTPS only.
- Test plane: the application under test is free to own LAN, Wi-Fi Direct, Bluetooth, NFC, or other radios.
- MUSABLAB instances never connect directly to each other.
- Each phone has a persistent random device ID and an independent GitHub inbox.

## Runtime path

`GitHub command -> native Android agent -> persistent Shizuku UserService -> local TestEngine -> report/evidence -> GitHub`

There is no Termux, `gh`, Python daemon, or `rish` in the production runtime.

## Speed model

GitHub only starts a complete local plan. UI/input/system steps execute locally through one already-bound Shizuku UserService. Conditional GET with ETag keeps the idle command poll inexpensive; the plan does not round-trip through GitHub between taps or assertions.

## Multi-device

Multi-device sessions use separate inboxes and reports. Cross-device orchestration will be performed by the central GitHub control plane, never by a direct socket between agents, to avoid contaminating Wi-Fi/Wi-Fi Direct/Bluetooth tests.

## Security boundaries

The v0.1 engine exposes typed test actions. It does not accept an arbitrary `shell` action in the GitHub plan. The privileged service is internal to the app and command strings are generated by typed handlers.
